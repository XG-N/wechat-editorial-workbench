# 审核模块：证据与状态

设计参考 `Humanizer-zh` 的信息保真核对、`markdownlint` 的规则编号和结构检查、`AutoCorrect` 的中英文混排检查，以及 `pycorrector` 的中文纠错方向。实际运行的是本项目的规则与代理复核；未冒称已经运行后三个外部工具。选型记录在研究目录。

## 五项实际语义复核

| 阶段 | 要核对的内容 | 通过依据 |
| --- | --- | --- |
| facts | 主张逐条对照资料，核数字、日期、单位、范围、因果与状态 | 台账能对应主张；无来源结论已删去或改为明确观点 |
| natural_style | 主题主线、具体信息、语气、机械排比、假对比、空话、聊天残留 | 语言自然且保留原意；不靠编经历或生造数据改善文风 |
| proofread_first | 全文错别字、漏字、重复、搭配、标点、专名 | 实际阅读全文并记录具体复核范围；疑问有处置 |
| proofread_final | 排版后再看主标题、副标题、正文、摘要、图注和署名 | 最终稿与图中文字一致；遗漏、裁切与文字问题已处理 |
| photos | 摄影身份、源页、作者、许可、实际像素与图注语境 | 已逐图看图；不是用下载成功代替审核 |

同一代理先后执行的两轮阅读，须如实称为代理双轮校对，不写成独立人工审校或多个模型交叉验证。用户需要独立审校时另行安排；普通文章不强制增加额外付费模型。

## 图文关系与视觉节奏

在`proofread_final`和`photos`中一并记录，参考[照片组合手册](photo-layout-rhythm.md)。先核文字与摄影关系，再看视觉：

- 图是否紧跟它所说明的段落；组合有没有跨章节搬图、使后续重点只剩文字。
- 手机宽度下主体是否仍能辨认；同组照片是否失衡、图注失去对应或短句挤成碎行。
- 连续单图是否缺少必要的组合变化；变化是否有内容依据，而非强制套两三种模板。
- 点缀是否依附具体图组或短句，面积合适，没有悬空撑高、抢走摄影主体或冒充机构标识。
- 主标题是否避开背景主体，分行是否保留原文；边框内缘是否给正文稳定的阅读面。

源稿相邻与纵横比检查能拒绝错误拼组，但不能证明视觉质量。实际看整篇与局部，用户指出单调或失衡时记录具体修复；不得用“无重叠”答复一个仍未解决的审美问题。没有合适图片的章节允许保留必要文字，不机械报“每章缺图”。

## 等级与处置

- `error`：已知疑似错字、主标题缺失、占位、来源或许可缺失、非摄影正文图、照片变化、HTML违规、动效缺失、旧复核指纹、未决语义问题。阻止导出和草稿上传。
- `warning`：上下文相关的文风提示。逐条核对后修复，或在 `acknowledged_warnings` 中记录规则ID并在复核说明写出保留理由。不能按词表机械删词。
- 无问题：仅代表本轮规则及已记录复核通过，不证明绝对零错字、事实全真、AI身份识别或平台兼容。

本地词表只处理少量常见错词。专名、语境错误、遗漏事实和的地得等仍需语义阅读。可扩展本地词表并加入回归例；不能用更长的词表冒充完整中文纠错模型。

## 可复核的记录

`review.json` 示例（实际做完才填写pass）：

```json
{
  "input_sha256": "fingerprint命令输出",
  "reviewer": "实际复核者与方式",
  "stages": {
    "facts": {"status": "pass", "notes": "核过哪些材料与主张"},
    "natural_style": {"status": "pass", "notes": "处理了哪些表达问题，保留哪些事实限定"},
    "proofread_first": {"status": "pass", "notes": "首轮全文核字与专名结果"},
    "proofread_final": {"status": "pass", "notes": "最终标题、摘要、图注和正文复读结果"},
    "photos": {"status": "pass", "notes": "逐图来源、许可与实际看图结果"}
  },
  "findings": [],
  "acknowledged_warnings": [],
  "wechat_verified": false
}
```

发现问题时用 `findings:[{rule,file,line,description,status,resolution}]` 保存修改闭环。`resolved` 表示实际修复；`accepted_with_reason` 仅用于可接受的上下文判断，不能豁免已知错别字或伪造事实。

指纹绑定文章、元数据、照片清单、事实台账、照片原下载件和使用件、最终HTML/预览/标题/封面，以及当前引擎与主题配置。它不绑定 `review.json` 自身，避免自循环。任何绑定内容变化，都需要重建并根据变化范围实际复核；不得自动把旧pass复制给新稿。

## 发布前四层状态

1. `blocked`：机器或语义审核未完成。
2. `ready_for_draft`：本地文章可进入草稿阶段。
3. `draft_created`：微信接口或后台已确认创建草稿；需要实际media_id或后台可见记录。
4. 微信客户端通过：手机中确认动态标题、图片、背景、排版和暗色效果。随后公开发布仍是单独动作。

`ready_for_draft` 不能写成“已发布”。浏览器工具失败、微信拒绝上传、缺凭据都要保留真实状态。

## 建议的可选增强

- 需要更广字词提示时，可单独评估 `pycorrector` 的本地模型；先看模型适用范围、下载体积和许可，不能自动下载大型模型或发送文章到陌生纠错站。
- `AutoCorrect` 可补充混排与标点建议，但它不等于全文中文语义纠错。
- `markdownlint` 可用于维护长文或多作者输入。代码与URL须保护，不能把外部通用规则直接套成产品硬要求。

# 暖橙校园报道版式

依据用户2026-10-22提供的校园活动公众号长截图学习。采用封面、底色、正文与图文组合的关系；手机状态栏、微信文章元信息、真实人物、活动事实、署名和二维码不属于可直接套用的模板内容。

## 版式配方

- 竖向暖橙插画封面，居中分行主标题，上半部有清楚的文字区域，下半部插画向奶油外框自然过渡。
- 奶油色外框 `#FFEFDB` 包住连续白色正文内页；内页约占宽度90%，内padding约4%，不逐段套卡片。
- 连贯正文采用系统黑体17px、1.83行高、0.25px字距、2em首行缩进；段后12px。原稿已有章名保留，使用18px半粗体，不删内容凑参考外观。
- 横向摄影可组成双图，保留各自出处，照片不重复、不生成替代现场。其他照片按信息作用保留单图。
- 未提供的作者、编辑、审核或组织身份不填；真实二维码缺失时整个区域省略。

## 可选元数据

```json
{
  "layout": "campus-warm",
  "hero_photo": "warm-cover",
  "hero_background": "designs/campus-paper-collage-v2.png",
  "frame_background": "designs/campus-frame-v2.jpg",
  "hero_title_lines": ["给周末留一段", "慢走的时间"],
  "hero_motion": "editorial-motion",
  "hero_title_top": 185,
  "hero_text_offset": 80,
  "hero_kicker": "",
  "hero_subtitle_lines": ["从熟悉的路口出发，", "不必赶往下一站"],
  "body_layout": "editorial-rhythm",
  "body_ornaments": {"intro": "walk-intro", "quote": "ginkgo-mark"},
  "photo_pairs": [],
  "photo_duos": [["sunlit-urban-steps-20261022", "sidewalk-shadows-20261022"]],
  "quote_photo": {"id": "park-bench", "quote": "散步可以没有一个值得汇报的结果。"}
}
```

`hero_title_lines` 拼合必须与文章主标题完全一致。背景应在 `photos.json` 登记为 `generated-background` 或有真实来源的摄影素材，匹配 `hero_photo` 的文件与SHA。生成背景说明实际工具与生成身份，正文摄影依旧逐图审核。

用户反馈“背景过于一般”后，新增整篇外框纹理：`frame_background` 需为登记过的生成背景，保存工具与SHA。根容器采用循环纸纹、金线与银杏装饰，白内页保持清楚阅读面，并保留奶油纯色兜底。预览会内嵌背景；API上传会把背景另存微信素材并核对读回URL。平台是否保留背景样式仍须真实账号验证，不能由本地通过推断。

`photo_pairs` 每组两个不同的照片ID，不能重复分组；必须都在正文中独立出现。组合放到两图原先较早的位置，仅移动图片与各自图注，不改变其他文字顺序。对依赖图位叙事的文章先核对段落语境，不机械配对。

用户进一步提供正文局部截图后，新增 `body_layout: ornament-staggered`：双图宽36:64，右图下移16px，图片依原比例完整显示。正文17px、1.88行高、0.35px字距、段后10px，引文改为细线之间的居中短句。布局依普通表格正常文档流，不依赖绝对定位或负边距。

用户在手机截图中指出错位图组失衡、第一章节无图后，曾采用 `body_layout: editorial-flow`。这一预设必须清空 `photo_pairs`，按Markdown源稿图位逐张展示，禁止跨章节自动调图。森林和枝叶横图全宽；竖图居中72%、最大300px，保持原比例。第一章节增加单独核实来源的真实街边台阶摄影，插在相应光影段落后，正文文字未改。其他文章也应先按段落安排照片，再考虑组合形式，避免开头集中用完配图。

连续阅读版采用3%外侧纹理、94%过渡面板、奶油到白色的窄内沿渐变，内部4%留边；正文17px、1.85行高、0.2px字距、段后10px。纯色奶油衬底保留，CSS渐变是否在微信中保留须真实账号核对。正文导入保留小插画，取消图组下的孤立装饰。

随后用户指出全篇逐张单图过于单调，当前示例采用 `editorial-rhythm`，保留以上阅读区、字体与标题，仅针对信息关系增加同题双图、照片与原短句并列。具体选择、源稿相邻条件、点缀与回退方法见[照片组合手册](photo-layout-rhythm.md)。没有合适素材的文章仍可采用连续单图。

`body_ornaments` 可指定正文导入 `intro` 与首组小图下的 `photo` 点缀，分别76px与46px。值是素材登记ID：`kind: generated-decoration`、`usage: decoration_only`，须有真实生成工具、生成身份说明、文件SHA，使用保留alpha的透明RGBA PNG。构建会核验身份和文件；点缀是非摄影插画，不混入Markdown摄影与照片数量。当前示例采用步道、长椅和银杏的纸艺小插画，不复制参考的学校标识、仪式建筑、烟花、红鸽或用户画的圈。

## 动效与导出

静态参考图不能证明其原文动效。本工具保留完整首帧，另用低强度装饰动态满足用户之前的动效要求。竖向GIF约1000×1260，附静态PNG；信息流横封面另作构图，避免居中裁切丢掉标题。

所有帧使用同一调色板与同一量化方法，防止背景循环色跳。源码、背景与输出均绑定审核指纹；修改后重建与复核。HTML不依赖JavaScript动画、外部CSS或绝对定位。

用户进一步要求首屏有明显动效后，可用 `hero_motion: editorial-motion`：32帧、3.84秒循环，祥云漂移、光晕与金点变化，标题上方500px始终稳定。透明差分编码压缩背景重复数据，全部解码帧依然不透明；不让静态文字随调色跳动。预览提供动态/静态切换，复制动态正文会恢复动图。默认accent预设仍保留轻量底部装饰。

封面文字位置可用 `hero_title_top`（140—230px）和 `hero_text_offset`（±80px）微调；`hero_subtitle_lines` 最多两行且拼合必须逐字等于副标题，类别标签可用空的 `hero_kicker` 省略。渲染记录文字像素框，越过左右安全边或动效500px保护区时阻止构建。本示例标题移至橙色净空处，副标题收成两行避开云纹，不把文字随背景移动。

当前阅读排版调整为系统黑体正文17px、1.83行高与0.25px字距，章名18px。图下使用编号中文短图注，完整摄影师、源页与许可链接集中于文末；竖图居中68%宽、最大320px，不裁切摄影内容。

## 本轮适配

新样例使用原散步稿作为版式练习，没有伪装为真实校园事件。第二版封面采用内置 `image_gen` 生成的纸艺拼贴、银杏、金线、匿名园林廊架和纸带步道；无字原图先生成，文字再由程序从已校对元数据排入。当前正文五张摄影为森林、街边台阶、树影、长椅与枝叶；原摄影文件未改，新增图库摄影不冒充用户亲历。完整提示词保存在样例designs/生图提示词与来源.json。

真实署名与二维码未提供，故省略。用户当前没有微信公众号账号；本地文件与媒体检查不能替代微信后台或手机验收。

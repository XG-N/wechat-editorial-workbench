# 项目产品推文流程

先确定文章用途和读者，再根据下列材料与结构制作。没有的事实保留缺口，不用模板补造。

## 最少需要的事实

- 读者要解决的具体问题、当前可用产品与使用入口
- 实际功能、截图、演示版本与已知限制
- 数据指标的测试条件、基线与证据；真实客户评价必须原话可追溯

## 两种可用结构

- 使用中的问题 → 一条实际操作路径 → 功能与收益 → 验证证据 → 适用范围 → 入口
- 触发场景 → 原方案问题 → 本次变化 → 前后可核对示例 → 使用条件

## 写作与去模板化

- 用功能和实际行为说明价值，减少赋能、颠覆、领先等无依据判断
- 把计划、开发、上线、交付、真实应用分别写清
- 不编客户、用户数量、团队履历或节省百分比

## 真实照片检索

- 用户提供的实际产品照片与授权截图
- 产品官方 press kit exact model
- Unsplash workspace photograph（仅背景，不作用户现场）

源页与许可逐张核对；下载原图并看图。图库是氛围，不能冒充活动现场、产品客户或到访记录。

## 版式配方

问题、路径和证据相邻；真实截图可作功能证据并清楚标为截图，不能冒充摄影。用户本轮要求正文照片真实，截图另列为证据附件。

动态主标题用完整首帧、缓慢局部装饰、主题背景与静态备份；正文不依赖网页动画。

## 专项审核

- 功能是否在所述版本可用
- 条件测算不能包装成实测收益
- 隐私、访问地址、演示账号和品牌授权须核对

再完成通用五项语义复核：事实、自然文风、首轮校对、最终校对和照片。指纹变化后重新核对。

## 可直接使用的制作指令

请围绕【主题】制作一篇面向【读者】的项目产品公众号文章。先核实材料和文章状态，选择本手册中适合的结构；缺少关键事实时只暂停依赖部分。正文自然具体，不编经历、引语、数字或效果；用真实且有使用依据的摄影配图。制作主标题GIF、适配背景和紧凑排版，做双轮全文校对与来源审核，交付预览、审核报告和可追溯文件包。

## 交付与下一步

正文Markdown、元数据、事实台账、照片清单、动态/静态标题、微信正文片段、预览、审核报告与SHA清单。实际后台草稿和手机效果必须分别核验，不能从本地通过推断。

执行通用工具与审核时，读取项目 `skills/wechat-editorial-pipeline/SKILL.md`，并使用 `tools/wechat.py`。用户只要求一个环节时完成该环节，不擅自上传或发布。
